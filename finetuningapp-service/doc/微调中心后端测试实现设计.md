## 1. 总体设计

### 1.1 设计目标

- **黑盒集成**：将 `finetuningapp-service` 视为黑盒，通过 API、DB、Kafka 三大外部接口进行交互和验证。
- **数据驱动**：核心测试逻辑（回放/清洗）强依赖数据，需构建可靠的 Kafka 数据生成（Protobuf）与验证（JSON）工具。
- **自动化闭环**：从提交任务到验证回调，实现全流程无人值守自动化。

### 1.2 技术栈

- **语言/框架**：Python 3 + `unittest` (或 `pytest`)
- **消息队列**：`confluent-kafka` (Python客户端) + `protobuf` (处理二进制消息)
- **HTTP**：`requests` (API调用), `http.server` (Mock回调)
- **数据库**：`psycopg2` (PostgreSQL访问)
- **运行方式**：`python -m unittest`

## 3. 公共基础设施实现

### 3.1 Kafka Helper (`utils/kafka_helper.py`)

**职责**：
1.  **Producer**: 序列化 Protobuf 对象并写入 Kafka（模拟 C++ 数据源）。
2.  **Consumer**: 订阅 Kafka 并反序列化 JSON 消息（验证 Java 产出）。
3.  **Protobuf**: 动态构建 `RawFlowMsg` 对象。

**核心接口示例**：

```python
class KafkaHelper:
    def __init__(self, brokers, output_topic):
        # 初始化 Producer 和 Consumer
        self.producer = Producer({'bootstrap.servers': brokers})
        self.consumer = Consumer({
            'bootstrap.servers': brokers,
            'group.id': 'test-verifier-group',
            'auto.offset.reset': 'latest'
        })
        self.consumer.subscribe([output_topic])

    def send_raw_flow(self, topic, ue_id, timestamp_ms, packet_count=100):
        """构造并发送 Protobuf 消息"""
        flow = raw_flow_pb2.RawFlowMsg()
        flow.ue_id = ue_id
        flow.timestamp = timestamp_ms
        flow.packet_count = packet_count
        # ... 填充其他必填字段 ...
        
        # 关键：Partition Key 必须是 ue_id，确保 Java 端 assign 正确
        self.producer.produce(
            topic=topic,
            key=ue_id.encode('utf-8'),
            value=flow.SerializeToString()
        )
        self.producer.flush()

    def wait_for_json_result(self, ue_id, timeout=30):
        """轮询等待指定 UE 的清洗结果"""
        start = time.time()
        while time.time() - start < timeout:
            msg = self.consumer.poll(1.0)
            if msg is None: continue
            if msg.error(): continue
            
            data = json.loads(msg.value().decode('utf-8'))
            if data.get('ue_id') == ue_id:
                return data
        return None
```

### 3.2 Mock Callback Server (`utils/mock_callback.py`)

**职责**：
启动一个临时的 HTTP Server，接收 Java 服务发出的 `POST /callbacks/notify` 请求，并存储请求内容供测试断言使用。

**实现思路**：
- 使用 Python 标准库 `http.server.HTTPServer`。
- 在独立线程中运行，避免阻塞测试主线程。
- 提供 `get_latest_callback(job_id)` 方法查询是否收到回调。

### 3.3 API Client (`utils/api_client.py`)

**职责**：
封装对微调中心 REST API 的调用，简化测试代码。

```python
class ApiClient:
    def submit_preprocess_task(self, ue_id, start_time, end_time):
        url = f"{self.base_url}/tasks/preprocess"
        payload = {
            "ue_id": ue_id,
            "time_range": {"start": start_time, "end": end_time},
        }
        resp = requests.post(url, json=payload)
        return resp.json() # 返回 task_id
```

### 3.4 BaseTestCase (`base.py`)

**职责**：
- `setUpClass`: 初始化 Kafka 连接、DB 连接，启动 Mock Server。
- `tearDownClass`: 清理资源，关闭 Mock Server。

## 4. 核心场景实现要点

### 4.1 FT-01: 预处理任务 E2E 测试 (`test_preprocess_e2e.py`)

**测试逻辑**：

1.  **Data Seeding (数据预置)**:
    - 生成一个唯一的 `test_ue_id`。
    - 确定一个测试时间窗口 `[T_start, T_end]`。
    - 调用 `KafkaHelper.send_raw_flow`，发送一条时间戳为 `T_mid` 的 Protobuf 消息（应被清洗保留）。
    - (可选) 发送一条时间戳在窗口外的消息（应被忽略）。

2.  **Action (动作)**:
    - 调用 `ApiClient.submit_preprocess_task` 提交任务。
    - 记录返回的 `task_id`。

3.  **Verification 1 (调度状态)**:
    - 轮询 DB，断言任务状态由 `PENDING` 变为 `RUNNING`。

4.  **Verification 2 (数据产出)**:
    - 调用 `KafkaHelper.wait_for_json_result(test_ue_id)`。
    - 断言收到的 JSON 数据中 `packet_count` 与预置的一致。

5.  **Verification 3 (异步回调)**:
    - 调用 `MockCallbackServer.get_latest_callback(task_id)`。
    - 断言收到回调，且 `status` 为 `SUCCESS`。
    - 断言 DB 中最终任务状态为 `SUCCESS`。

**代码片段示例**：

```python
def test_e2e_preprocess_flow(self):
    # 1. Prepare Data
    ue_id = f"auto-test-{uuid.uuid4().hex[:8]}"
    now_ms = int(time.time() * 1000)
    
    self.kafka.send_raw_flow(
        topic=config.TOPIC_RAW, 
        ue_id=ue_id, 
        timestamp_ms=now_ms, # 在时间窗口内
        packet_count=100     # > 阈值
    )
    
    # 2. Submit Task
    task_id = self.api.submit_preprocess_task(
        ue_id=ue_id,
        start_time=now_ms - 60000, # 前1分钟
        end_time=now_ms + 60000,   # 后1分钟
    )
    
    # 3. Verify Output (Kafka)
    result = self.kafka.wait_for_json_result(ue_id, timeout=30)
    self.assertIsNotNone(result, "Should receive cleaned data")
    self.assertEqual(result['packet_count'], 100)
    
    # 4. Verify Callback
    callback = self.mock_server.wait_for_callback(task_id)
    self.assertEqual(callback['status'], 'SUCCESS')
```

## 5. 环境与配置

### 5.1 配置文件 (`config.py`)

需包含以下环境变量或默认值：

- `KAFKA_BOOTSTRAP_SERVERS`: Kafka 地址
- `DB_CONNECTION_STRING`: PostgreSQL 连接串
- `API_BASE_URL`: 被测服务地址 (e.g., http://localhost:8080/api/finetuning/v1)
- `TEST_HOST`: 运行测试的机器 IP (供 Java 回调)
- `APP_DIALING_SERVICE_URL`: **关键**。Java 服务需配置此环境变量指向 `http://{TEST_HOST}:{MOCK_PORT}`，以便将回调发送给 Mock Server。

### 5.2 依赖准备

运行测试前需执行：
1.  `pip install -r requirements.txt`
2.  编译 Protobuf: `protoc -I=proto --python_out=generated proto/raw_flow.proto`
