### 2.2 修复了日期时间类型问题

**问题**: 原始 YAML 使用了 `format: date-time`，导致生成的代码使用了 `org.threeten.bp.OffsetDateTime`，造成编译错误。

**解决方案**: 将所有 `format: date-time` 移除，统一使用 `type: string` 并在 description 中注明 "ISO-8601 datetime string"，与项目中其他 API 的风格保持一致。

**修改的字段**:
- `TaskStatusData.create_time` (第467-469行)
- `TaskStatusData.start_time` (第470-472行)
- `TaskStatusData.end_time` (第473-475行)
- `ModelVersion.create_time` (第505-507行)
- `SampleStats.last_update_time` (第552-554行)

## 3. 遇到并解决的问题

### 3.1 日期时间类型编译错误

**问题描述**:
使用 `format: date-time` 导致 swagger-codegen 生成了依赖 `org.threeten.bp` 包的代码，但项目中没有这个依赖。

**错误信息**:
```
[ERROR] 找不到符号
  符号:   类 OffsetDateTime
  位置: 类 com.huawei.cloududn.finetuningapp.model.TaskStatusData
```

**解决方案**:
参考项目中其他 API（executor-api.yaml），使用 `type: string` 并在 description 中注明格式，而不是使用 `format: date-time`。

## 6. 关键决策记录

### 6.1 时间字段使用字符串类型

**决策**: 所有时间字段使用 `type: string` 而不是 `type: string, format: date-time`

**原因**:
1. 与项目现有 API 风格保持一致
2. 避免引入 `org.threeten.bp` 依赖
3. 简化客户端处理（直接使用 ISO-8601 字符串）

### 6.2 包名隔离

**决策**: 微调中心使用独立的包名 `com.huawei.cloududn.finetuningapp`

**原因**:
1. 与拨测业务 (`dialingtest`) 逻辑隔离
2. 便于未来拆分成独立微服务
3. 避免类名冲突
