## 1. 总体设计

### 1.1 设计目标

- **职责分离**：  
  - `测试场景设计`：定义测试目标、步骤、验证点（WHAT）  
  - `测试实现设计`：定义测试代码结构、工具和实现方式（HOW）
- **最小重复**：业务流程、字段含义不在本文重复，只引用场景设计中的IT编号。
- **易实现**：为Python测试工程提供直接可落地的结构和示例。
- **可扩展**：新增IT场景时，只需要在两个文档中分别补充场景描述和实现方案。

### 1.2 技术栈与边界

- **语言/框架**：Python 3 + `unittest`
- **通信**：`websocket-client`（支持Text/Binary消息）
- **HTTP**：`requests`
- **数据库**：`psycopg2` 访问PostgreSQL
- **加解密/编码**：`hashlib`（SHA256）、`base64`、`binascii`（Hex）、`zlib`（CRC32）
- **测试运行方式**：命令行运行 `python -m unittest` 或 `pytest`（可选）

> 说明：Python测试工程作为黑盒集成测试，不直接访问Java代码，只通过WebSocket/HTTP/DB与后端交互。

### 3.2 V5双连接WebSocket客户端封装（`dual_ws_client.py`）⚠️ 核心变更

**目的**：管理**两条独立的WebSocket连接**（控制链路和数据链路），实现V5物理分离架构。

**核心职责**：
- 管理控制链路连接（`/ws/executor/control`）
- 管理数据链路连接（`/ws/executor/data`）
- 自动路由JSON消息到控制链路
- 自动路由Binary消息到数据链路
- 处理Token绑定流程
- 双连接状态同步

**关键设计**：

```python
class DualWebSocketClient:
    """V5双连接WebSocket客户端"""
    
    def __init__(self, control_url: str, data_url: str, timeout: int = 30):
        self.control_url = control_url  # wss://server/ws/executor/control
        self.data_url = data_url        # wss://server/ws/executor/data
        self.timeout = timeout
        
        self.control_ws = None          # 控制链路连接
        self.data_ws = None             # 数据链路连接
        self.token = None               # 认证token
        self.is_bound = False           # 数据链路是否已绑定
    
    def connect_all(self):
        """建立双连接"""
        # 1. 先建立控制链路
        self.control_ws = websocket.create_connection(
            self.control_url, timeout=self.timeout
        )
        logging.info("Control link connected")
        
        # 2. 再建立数据链路
        self.data_ws = websocket.create_connection(
            self.data_url, timeout=self.timeout
        )
        logging.info("Data link connected")
    
    def authenticate_and_bind(self, username: str, password_hash: str):
        """执行CHAP认证并绑定数据链路"""
        # 1. 通过控制链路完成CHAP认证
        self.token = self._do_chap_auth(username, password_hash)
        logging.info(f"Authentication successful, token={self.token}")
        
        # 2. 通过数据链路发送token绑定消息
        self._bind_data_link(self.token)
        logging.info("Data link bound successfully")
        self.is_bound = True
    
    def send_json(self, envelope: dict):
        """发送JSON消息 - 自动通过控制链路"""
        if self.control_ws is None or not self.control_ws.connected:
            raise RuntimeError("Control link not connected")
        self.control_ws.send(json.dumps(envelope))
        logging.debug(f"JSON sent via control link: {envelope['type']}")
    
    def recv_json(self, timeout: Optional[int] = None) -> dict:
        """接收JSON消息 - 自动从控制链路"""
        raw = self.control_ws.recv()
        return json.loads(raw)
    
    def send_binary(self, data: bytes):
        """发送Binary消息 - 自动通过数据链路"""
        if not self.is_bound:
            raise RuntimeError("Data link not bound yet")
        if self.data_ws is None or not self.data_ws.connected:
            raise RuntimeError("Data link not connected")
        self.data_ws.send(data, opcode=websocket.ABNF.OPCODE_BINARY)
        logging.debug(f"Binary sent via data link: {len(data)} bytes")
    
    def recv_binary(self, timeout: Optional[int] = None) -> bytes:
        """接收Binary消息 - 自动从数据链路"""
        frame = self.data_ws.recv_frame()
        return frame.data
    
    def close_all(self):
        """关闭双连接"""
        if self.control_ws:
            self.control_ws.close()
        if self.data_ws:
            self.data_ws.close()
        logging.info("Both links closed")
    
    def _do_chap_auth(self, username: str, password_hash: str) -> int:
        """通过控制链路完成CHAP认证（详细实现见IT-01）"""
        # 发送Register-Request，接收Challenge，发送Response，接收Result
        # 返回token
        pass
    
    def _bind_data_link(self, token: int):
        """通过数据链路发送token绑定消息"""
        auth_msg = {"type": "DataLinkAuth", "token": token}
        self.data_ws.send(json.dumps(auth_msg))
```

**使用示例**：

```python

    control_url="wss://localhost:8443/ws/executor/control",
    data_url="wss://localhost:8443/ws/executor/data"
)

# 1. 建立双连接
client.connect_all()

# 2. 认证并绑定

# 3. 发送JSON（自动走控制链路）

# 5. 关闭

```

### 3.3 JSON信封处理（`json_message.py`）

**职责**：
- 保证所有发送的消息遵循通信协议设计中的信封格式：

```json
{
  "type": "RegisterRequest",
  "token": 1234567890123456,
  "payload": { ... }
}
```

**关键接口**：

```python
class JsonMessageHelper:
    def build(self, msg_type: str, payload: dict, token: Optional[int] = None) -> dict:
        env = {"type": msg_type, "payload": payload}
        if token is not None:
            env["token"] = token
        return env

    def parse(self, data: dict) -> Tuple[str, Optional[int], dict]:
        return data["type"], data.get("token"), data["payload"]
```

> 所有测试场景只关心业务payload，信封的构造和解析统一通过该工具类处理，避免重复代码与格式错误。

def test_dual_connection_establish_success(self):
    """测试双连接成功建立和绑定"""
    client = DualWebSocketClient(self.config.control_url, self.config.data_url)
    
    # 1. 建立双连接
    client.connect_all()
    self.assertTrue(client.control_ws.connected)
    self.assertTrue(client.data_ws.connected)
    
    # 2. 认证并绑定

## 7. V5新增测试场景实现 ⚠️ 重要

### 7.1 IT-10：物理隔离优势测试（跨链路隔离）

**测试类**：`TestLinkIsolation`  
**文件**：`test_link_isolation.py`

**测试目标**：验证V5核心优势 - 控制消息不受数据传输影响

**实现要点**：

```python
def test_control_not_blocked_by_data_transfer(self):
    """测试大文件传输期间控制消息仍能即时响应"""
    client = DualWebSocketClient(...)
    client.connect_all()
    client.authenticate_and_bind(...)
    
    # 1. 启动大文件传输（数据链路）
    import threading
    def send_large_file():
        for i in range(1000):  # 100MB文件
            client.send_binary(b'0' * 102400)  # 100KB chunks
            time.sleep(0.01)
    
    transfer_thread = threading.Thread(target=send_large_file)
    transfer_thread.start()
    
    # 2. 在传输期间发送心跳（控制链路）
    time.sleep(0.5)  # 等待传输开始
    start_time = time.time()
    client.send_json({"type": "ReportMsg", "token": client.token, ...})
    response = client.recv_json()
    latency = time.time() - start_time
    
    # 3. 验证心跳延迟极低
    self.assertLess(latency, 0.01)  # <10ms
    
    # 4. 清理
    transfer_thread.join()
```

**性能指标**：
- 控制消息延迟必须 < 10ms
- 心跳、停止命令在大文件传输期间正常工作
